Orders

Estimate an order

POST /{org}/sites/{site}/orders/preview

Base URL https://api.adobecommerce.live

Staging https://api-stage.adobecommerce.live

Computes tax, shipping, and discounts for the cart against the selected shipping method and returns a signed estimateToken. reCAPTCHA-gated for unauthenticated callers.

Response

200 The estimate and signed token. Line allocations are server-calculated; bundle component allocations sum to and replace the parent allocation for component-line consumers, so never subtract both levels. price.final is the submitted price, validated against the catalog: the item's stored price or, while a catalog promotion is active for it, its promotional price. A bundle parent at its promotional price has that price apportioned across its bundleItems in proportion to their stored prices, so component price.final values sum to the parent's.

Reports each submitted code as applied, rejected_invalid (failed validation; reason withheld to prevent code enumeration), or rejected_not_combinable (valid but not part of the winning stacking combination).

400 The preview was rejected, for example: it is invalid (ADOBE_COMMERCE_VALIDATION_FAILED, with per-field errors: the body failed validation, shippingMethod.id is missing, or the selected method is unavailable); it references a product path or SKU that does not exist (ADOBE_COMMERCE_REFERENCED_NOT_FOUND); or it is not consistent with the catalog (ADOBE_COMMERCE_CONSISTENCY_MISMATCH, with details.field such as price, bundle_price, or bundle_variant).

FieldTypeRequiredDescription

messagestringyesHuman-readable error message.
resourcestringnoThe resource type involved, when applicable.
errorsobject[]noPer-field validation failures (present on ADOBE_COMMERCE_VALIDATION_FAILED).
detailsobjectnoOptional structured detail; fields vary by error. For example, ADOBE_COMMERCE_REFERENCED_NOT_FOUND carries path or sku; ADOBE_COMMERCE_CONSISTENCY_MISMATCH carries field, e.g. price (an item's submitted price matches neither its stored price nor its active catalog promotion price; actualPrice is the effective final price the client should use, after any active catalog promotion is applied), bundle_price (a bundle's price does not match its components, and is not its promotional price), or bundle_variant (the selected options do not resolve to exactly one bundle variant).

422 An unauthorized free ($0) item was requested with no matching free-item grant.
