Catalog

Bulk write or delete products

POST /{org}/sites/{site}/catalog

Base URL https://api.adobecommerce.live

Staging https://api-stage.adobecommerce.live

Unified bulk catalog endpoint. Accepts an { items } envelope and, by default, creates or updates (upserts) each product (max 50 per request). In write mode, unchanged products are skipped (status 200); pass ?forceUpdate=true (or a body forceUpdate: true alias) to write and re-index every item regardless, e.g. after an index-configuration change. Setting ?delete=true (or a body delete: true alias) switches to bulk delete, whose items are { path } objects carrying an extensionless product path. When both selectors are present they must agree. Every item is validated up front, so a single invalid item rejects the whole request and nothing is written or deleted. Deletes are unconditional and deduplicated. In delete mode, pass ?forceUpdate=true (or a body forceUpdate: true alias) to emit an index-removal event even for items that are already gone from the catalog (404), clearing orphaned index entries. Always responds with a results array, one entry per distinct item (extensionless paths), including for single-item requests. Each delete result is independent: 200 deleted, 404 not found, 500 failed. Delete request example: { "items": [{ "path": "/us/en/products/blender-pro-500" }, { "path": "/us/en/products/blender-pro-750" }] } with ?delete=true.

Required permissions: catalog:write

Path parameters

NameTypeRequiredDescription
orgstringyesOrganization identifier.
sitestringyesSite identifier.

Query parameters

NameTypeRequiredDescription
deletebooleannoWhen true, the request is a bulk delete; false (or absent) is a write. Canonical selector; the body delete flag is an alias that must agree when both are present.
forceUpdatebooleannoWhen true, write and re-index each product even if its data is unchanged. Unchanged products are otherwise skipped (reported with status 200); use this after an index-configuration change to force a re-index. In bulk delete mode, forceUpdate also emits an index-removal event for products that are already gone from the catalog (404), clearing orphaned index entries.
