Payments

Confirm (capture) an approved order

POST /{org}/sites/{site}/orders/{orderId}/payments/confirm

Base URL https://api.adobecommerce.live

Staging https://api-stage.adobecommerce.live

Requires the order to be in payment_requires_confirmation. Serializes concurrent confirms so only one capture is sent; duplicates replay the stored result or receive a retryable 503. No authentication required.

Path parameters

NameTypeRequiredDescription
orgstringyesOrganization identifier.
sitestringyesSite identifier.
orderIdstringyesOrder identifier (full or friendly id).

Request headers

NameTypeRequiredDescription
AuthorizationstringnoBearer token. Bearer <jwt>. Optional — guest checkout is supported.
Content-TypestringyesMust be application/json.

Request body

FieldTypeRequiredDescription
idempotencyKeystringyesCaller-supplied idempotency key; replays return the prior result.

Response

200 The confirm result — { status: "completed", ... }, { status: "pending", ... }, or { status: "failed", checkoutFailure, cancelled }, where checkoutFailure is "contact_support" or "retry" — the customer-safe outcome the storefront renders. On a failed confirm, cancelled: true means the order is now terminal (payment_cancelled) and the buyer must restart from the cart; cancelled: false is not currently returned (a transient failure yields a retryable 503 instead).
