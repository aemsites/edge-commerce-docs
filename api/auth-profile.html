Auth

Validate the token and return the caller identity

GET /{org}/sites/{site}/auth/profile

Base URL https://api.adobecommerce.live

Staging https://api-stage.adobecommerce.live

Path parameters

NameTypeRequiredDescription
orgstringyesOrganization identifier.
sitestringyesSite identifier.

Request headers

NameTypeRequiredDescription
AuthorizationstringnoBearer token. Bearer <token>. Required unless the auth_token cookie is sent.
CookiestringnoOptional auth_token cookie carrying the session JWT.

Response

200 The token is valid; the caller's identity is returned.

HeaderDescription
Content-Typeapplication/json
Cache-Controlprivate, no-store
FieldTypeRequiredDescription
emailstring | nullyesCaller email. Null for anything other than a session token.
orgstring | nullyesOrg the credential is scoped to; null for operator credentials.
sitestring | nullyesSite the credential is scoped to; null for operator credentials.
rolesstring[]yesResolved roles: ["user"] or ["admin", "user"] for session tokens, ["service"] for legacy site keys, ["superuser"] for operator credentials, and empty for JWT service tokens (which carry permissions directly).
permissionsstring[]yesPermissions granted to the credential. Read this as the grants, not as a complete permission check: JWT service tokens return their raw grants, which may include scoped entries such as emails:send:*@example.com that the API matches by pattern against the request (here, the recipient address), and operator (superuser) credentials bypass permission checks entirely, so their list understates what they can do.
serviceTokenbooleanyesTrue only for JWT service tokens (/auth/service_token); false for legacy site keys.
issuedAtnumber | nullyesJWT iat (seconds since epoch); null for non-JWT credentials.
expiresAtnumber | nullyesJWT exp (seconds since epoch); null for non-JWT credentials.

401 Missing, malformed, or expired token: ADOBE_COMMERCE_UNAUTHORIZED (unauthorized). Revoked (logged-out) token: ADOBE_COMMERCE_TOKEN_REVOKED (token revoked).
